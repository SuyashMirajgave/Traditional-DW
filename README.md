
# Traditional Data Warehouse and Retail Sales Business Intelligence System

## Project Overview

This project demonstrates how a traditional data warehouse can be used to analyze retail sales data.

The system uses PostgreSQL to store source data and a separate warehouse database for analytical reporting. Python automates the ETL process, and Streamlit displays the results through an interactive dashboard.

## Project Objectives

- Design a source database and a dimensional data warehouse.
- Implement a star schema.
- Extract, transform, and load data using Python.
- Analyze sales by product, category, region, and month.
- Build an interactive business intelligence dashboard.
- Export filtered sales records to CSV.

## Technologies Used

- Python
- PostgreSQL
- Docker
- SQL
- Pandas
- Plotly
- Streamlit
- psycopg2
## Project Architecture

The project follows a traditional data warehouse workflow.

1. **Source Database:** Stores the original retail data, including products, regions, and sales orders.
2. **ETL Pipeline:** A Python script extracts data from the source database and loads it into the data warehouse.
3. **Data Warehouse:** Stores organized data in dimension tables and a fact table for analytical queries.
4. **SQL Analytics:** Uses SQL queries to analyze revenue, products, categories, regions, and monthly sales.
5. **BI Dashboard:** A Streamlit dashboard presents sales metrics and interactive charts, with filters and CSV export.

### Workflow

```text
Retail Source Database
          |
          v
    Python ETL Pipeline
          |
          v
  Retail Data Warehouse
          |
          v
      SQL Analytics
          |
          v
  Streamlit BI Dashboard
```
## Database Design

The project uses two PostgreSQL databases: `retail_source` and `retail_warehouse`.

### 1. Source Database — `retail_source`

This database stores the original retail business data.

| Table | Purpose |
|---|---|
| `products` | Stores product information, including product names and categories. |
| `regions` | Stores region information, including region names and states. |
| `sales_orders` | Stores retail sales orders, quantities, prices, and related information. |

### 2. Data Warehouse — `retail_warehouse`

This database organizes data for business intelligence and reporting.

| Table | Purpose |
|---|---|
| `dim_date` | Stores date details such as day, month, quarter, and year. |
| `dim_region` | Stores region details for geographical sales analysis. |
| `dim_product` | Stores product details for product and category analysis. |
| `fact_sales` | Stores sales transactions, quantities, prices, revenue, and links to the dimension tables. |

### Data Warehouse Schema

The warehouse follows a **star schema** design. The `fact_sales` table is the central fact table, connected to the date, region, and product dimension tables through foreign keys.

This structure supports analytical queries without relying only on the original transactional database.
## ETL Pipeline

The ETL process is implemented using Python in `etl/etl_pipeline.py`.

ETL stands for **Extract, Transform, and Load**.

### ETL Process

1. **Extract:** Connects to the `retail_source` database and retrieves data from the source tables.
2. **Transform:** Prepares the extracted data for the data warehouse, including date-related information required for analysis.
3. **Load:** Inserts or updates data in the dimension tables and the `fact_sales` table in `retail_warehouse`.

### ETL Features

- Automates the transfer of retail sales data.
- Loads product and region dimensions.
- Creates date dimension records required for sales analysis.
- Loads sales transactions into the fact table.
- Supports rerunning the pipeline without creating duplicate fact records for existing order IDs.

### How to Run the ETL Pipeline

Activate the project's Python virtual environment and run:

```bash
source .venv/bin/activate
python etl/etl_pipeline.py
```

Make sure Docker Desktop is running and the PostgreSQL container is available before executing the pipeline.
## SQL Analytics

SQL queries are stored in `analytics/01_sales_analysis.sql`.

These queries analyze the data stored in the `retail_warehouse` database and help identify important business trends.

### Analyses Performed

1. **Overall Sales Performance:** Calculates key sales metrics.
2. **Product-wise Revenue:** Identifies revenue generated by individual products.
3. **Monthly Revenue Trend:** Analyzes how revenue changes over time.
4. **Region-wise Revenue:** Compares sales performance across regions.
5. **Category-wise Performance:** Evaluates revenue across product categories.

### Business Value

These analyses help a retail business understand which products generate more revenue, how sales change over time, which regions perform well, and which product categories contribute most to overall sales.
## Business Intelligence Dashboard

The interactive dashboard is developed using Streamlit, Pandas, and Plotly. Its Python code is located in `dashboard/app.py`.

### Dashboard Features

- **Sales Overview:** Displays total orders, units sold, total revenue, and average order value.
- **Monthly Revenue Chart:** Shows revenue trends over time.
- **Product-wise Revenue Chart:** Compares revenue generated by different products.
- **Category-wise Revenue Chart:** Displays revenue by product category.
- **Region-wise Revenue Chart:** Compares sales performance across regions.
- **Interactive Filters:** Allows users to filter sales data by date, product, category, and region.
- **Sales Details:** Displays filtered sales records in a table.
- **CSV Export:** Allows users to download the filtered sales data.

### How to Run the Dashboard

First, make sure Docker Desktop is running and the PostgreSQL container is available. Activate the project's virtual environment and run:

```bash
source .venv/bin/activate
streamlit run dashboard/app.py
```

Open the local URL displayed in the terminal, usually `http://localhost:8501`, in your web browser.

## Installation and Database Setup

### 1. Start PostgreSQL

Make sure Docker Desktop is running. Open a terminal in the project root directory and run:

```bash
docker compose up -d
```

This starts the PostgreSQL container defined in `docker-compose.yml`.

### 2. Create the Source Database Tables

The `retail_source` database is created automatically when the PostgreSQL container is initialized for the first time.

Run the source schema script:

```bash
docker exec -i traditional_dw_postgres psql -U dwuser -d retail_source < sql/01_source_schema.sql
```

Load the sample retail data:

```bash
docker exec -i traditional_dw_postgres psql -U dwuser -d retail_source < sql/02_sample_data.sql
```

**Note:** Run the sample-data script only once on a fresh database to avoid duplicate records.

### 3. Create the Warehouse Database

Create the warehouse database:

```bash
docker exec -it traditional_dw_postgres psql -U dwuser -d retail_source -c "CREATE DATABASE retail_warehouse;"
```

Then create its tables:

```bash
docker exec -i traditional_dw_postgres psql -U dwuser -d retail_warehouse < sql/03_warehouse_schema.sql
```

### 4. Install Python Dependencies

Create and activate a virtual environment, then install the required packages:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 5. Run the ETL Pipeline

```bash
python etl/etl_pipeline.py
```

### 6. Launch the Dashboard

```bash
streamlit run dashboard/app.py
```

Open `http://localhost:8501` in your browser.
## Running the Project on Windows

The project can be set up on Windows using Docker Desktop, Python, and a terminal such as PowerShell.

### Requirements

- Windows 10 or Windows 11
- Docker Desktop
- Python 3
- PowerShell
- A copy of this project folder

### Setup Steps

1. Install and start Docker Desktop.
2. Open PowerShell in the project folder.
3. Start PostgreSQL:

```powershell
docker compose up -d
```

4. Run the SQL schema and sample-data scripts using the PostgreSQL container. The exact commands depend on the terminal being used; the commands in the main installation section use Unix-style input redirection and are intended for macOS/Linux shells.
5. Create and activate a Python virtual environment:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

6. Install Python dependencies:

```powershell
python -m pip install -r requirements.txt
```

7. Run the ETL pipeline:

```powershell
python etl/etl_pipeline.py
```

8. Start the dashboard:

```powershell
python -m streamlit run dashboard/app.py
```

9. Open `http://localhost:8501` in a browser.

### Cross-Platform Note

The Python and SQL files are shared between macOS and Windows. However, Docker commands, shell syntax, Python environment activation, and database connection settings must be configured correctly for the computer being used.

The database setup scripts should be run in the correct order, and the sample data should be loaded only once into a fresh source database.
